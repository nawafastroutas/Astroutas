# قواعد Realtime Database الخاصة بالأقسام

الموقع يحفظ «أقسام السبح» في المسار:

```
subbha/rosaryCategories
```

إن كانت قواعد قاعدة البيانات لا تسمح بالكتابة في هذا المسار، فسيظهر لك في
تبويب «أقسام السبح» شريطٌ أحمر مكتوب فيه `PERMISSION_DENIED`. عندها يبقى
التعديل محفوظاً على جهازك، لكنه **لن يصل لبقية الزوار** حتى تُعدَّل القواعد.

## الإصلاح (دقيقة واحدة)

1. افتح [Firebase Console](https://console.firebase.google.com) → مشروع
   `ubhha-dd0e9` → **Realtime Database** → تبويب **Rules**.
2. أضف الكتلة التالية **داخل** قواعدك الحالية — لا تستبدل الملف كله، وإلا
   تعطّلت بقية أجزاء الموقع (المنتجات، الطلبات، الإشعارات…):

```json
"subbha": {
  "rosaryCategories": {
    ".read": true,
    ".write": "auth != null"
  }
}
```

إن كان لديك بالفعل مفتاح `"subbha"` فأضف `"rosaryCategories"` بداخله فقط.

3. اضغط **Publish**.
4. ارجع للموقع، افتح تبويب «أقسام السبح» واضغط **إعادة المحاولة الآن**.
   يجب أن يتحول الشريط إلى الأخضر: «محفوظ ومتزامن».

> `".write": "auth != null"` تعني أن المشرف المسجَّل دخوله فقط يستطيع التعديل،
> والزوار يقرأون فقط. هذا هو الإعداد الموصى به.

## مسارات بديلة (تلقائية)

إن ظل المسار الأساسي مرفوضاً، يجرّب الموقع تلقائياً — وبالترتيب —:

1. `subbha/rosaryCategories`  ← المسار الرسمي
2. `subbha/settings/rosaryCategories`
3. `rosaryCategories`

وأول مسارٍ يقبل الكتابة يصبح هو المستخدَم، ويُحفظ اختياره. كل المسارات
تُقرأ معاً ويُعتمد السجل الأحدث، فلا تتفرّق النسخ بين الأجهزة.
