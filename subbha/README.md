# Subbha — موقع سبحة

هذا هو ملف الموقع الكامل (`index.html`) مع مجلد الصور `assets/`.

---

## ١) الشعار صار داخل `index.html`

كان الشعار يُقرأ من ملف خارجي:

```html
<img src="assets/subbha-40ed1cc645348888.png">
```

فإذا رُفع `index.html` وحده — أو لم يُرفع مجلد `assets` معه — يظهر مربع فارغ
مكان الشعار.

الآن الصورة **مضمَّنة داخل الملف نفسه** بصيغة `data:image/png;base64,…`،
في المواضع الستة كلها (الهيدر، الواجهة، قسم «عن سبحة»، الفاتورة، …)،
وأُضيف أيضاً **أيقونة التبويب (favicon)** من الشعار نفسه — لم تكن موجودة.

النتيجة: **الشعار يظهر دائماً**، حتى لو رفعتَ `index.html` وحده، أو فتحتَه
من الجهاز مباشرة بدون إنترنت.

> ملاحظة: صور الخرز والطرابيش (١٥ صورة) ما زالت في `assets/`؛ لم أضمّنها
> لأن حجمها ٣ ميجابايت وستُبطئ الموقع. فارفع مجلد `assets` معه كالمعتاد —
> الشعار وحده هو ما لن يعتمد عليه بعد الآن.

## ٢) تعديل/إضافة الأقسام صار يعمل

### السبب الحقيقي

كان معالج حفظ القسم يبدأ بهذا السطر:

```js
if (e.target.id !== 'rosaryCategoryForm') return;
```

ونموذج القسم يحتوي على حقل اسمه `id`:

```html
<input type="hidden" name="id" value="…">
```

وفي HTML، عندما يحتوي `<form>` على حقلٍ اسمه `id`، فإن `form.id` تُرجع **ذلك
الحقل** لا قيمة المعرّف (خاصية `LegacyOverrideBuiltIns` في المواصفة). فكانت
المقارنة تفشل **دائماً**، ويخرج المعالج من أول سطر — ولهذا كان الضغط على
«إضافة القسم» أو «حفظ التعديل» **لا يفعل شيئاً إطلاقاً**: لا رسالة خطأ،
ولا حفظ محلي، ولا مزامنة.

الإصلاح:

```js
if (e.target.getAttribute?.('id') !== 'rosaryCategoryForm') return;
```

### ومشكلة ثانية كانت ستظهر بعدها

كانت دالة `saveCategories` تُلغي تعديلك المحلي إن فشلت الكتابة في السحابة:

```js
if (!firebaseDB) { rosaryCategories = previous; … return false; }   // يتراجع
catch (e)       { rosaryCategories = previous; … return false; }   // يتراجع
```

وأسوأ من ذلك: `firebase.ref().set()` **لا يُحسم أبداً** عند انقطاع الإنترنت
(لا ينجح ولا يفشل)، فكان `await` يعلّق إلى الأبد والواجهة تتجمّد بلا رسالة.

صار الحفظ الآن **محلياً أولاً ثم مزامنة في الخلفية**:

| الحالة | ماذا يحدث الآن |
|---|---|
| السحابة تعمل | يُحفظ محلياً + يُرفع فوراً + شريط أخضر «محفوظ ومتزامن» |
| لا يوجد إنترنت | يُحفظ محلياً ويبقى بعد إعادة التحميل، ويُرفع تلقائياً عند عودة الاتصال |
| القواعد ترفض الكتابة | يُحفظ محلياً، ويظهر سبب الرفض بوضوح مع زر «إعادة المحاولة» وشرح القواعد المطلوبة |
| المسار الأساسي مرفوض | يُجرَّب مسار بديل تلقائياً |
| جهاز آخر عدّل الأقسام | يصل التعديل ويُعرض، دون أن يمسح تعديلاً محلياً أحدث لم يُرفع بعد |

أُضيف أيضاً **شريط حالة المزامنة** أعلى تبويب «أقسام السبح» يقول لك بالضبط
أين وصل التعديل، ومهلة ١٢ ثانية لأي عملية رفع حتى لا تتجمّد الواجهة أبداً.

> إن ظهر لك `PERMISSION_DENIED`، فالمشكلة في قواعد قاعدة البيانات لا في
> الموقع — الحل في [`FIREBASE-RULES.md`](FIREBASE-RULES.md) ويأخذ دقيقة.
