## الملفات

```
index.html    المسرح — ٩ مشاهد، كل مشهد يحمل --t0 (بدايته) و--dur (مدته)
scene.css     كل التصميم وكل الحركة
scene.js      يبني العناصر المتكررة فقط (خرز، خيوط، ومضات) — لا حركة فيه
render.mjs    يلتقط الإطارات ويبني الـ MP4
preview.mjs   لقطات عند لحظات محدّدة، للمعاينة أثناء التعديل
brand/        الشعار الأصلي + النسخ المفرّغة
fonts/        الخطوط (مضمّنة حتى يظهر الملف كما هو على أي جهاز)
output/       الفيديو وصورة الغلاف
```

## التشغيل

```bash
# معاينة في المتصفح (؟fit يصغّر المسرح ليناسب النافذة)
npx http-server -p 8080 -c-1 .     # ثم افتح  http://localhost:8080/?fit

# إعادة بناء الفيديو
node render.mjs                     # الوضع الافتراضي: ٣٠ إطار/ث
node render.mjs --fps 60            # أنعم، وملف أكبر
node render.mjs --keep              # يُبقي ملفات الإطارات في .frames/
```

يحتاج `ffmpeg` و`playwright` (كلاهما مثبّت في بيئة التطوير هذه).

### كيف يُضمن أن الفيديو مطابق في كل مرة

كل حركة في المشهد هي CSS animation لها `animation-delay` **مطلق** على خط زمني
واحد يبدأ من الصفر. يفتح `render.mjs` الصفحة، يُجمّد كل الحركات، ثم يضبط
`currentTime` لكل حركة على لحظة الإطار قبل كل لقطة. فالنتيجة لا تعتمد على سرعة
الجهاز ولا على ساعة النظام: نفس الإطار بالبكسل في كل تشغيل.

ولهذا لا يوجد `requestAnimationFrame` ولا `setTimeout` في `scene.js` إطلاقًا.

**ملاحظة:** التصيير يتقدّم للأمام فقط. المتصفح يُسقِط الحركات المنتهية من
`document.getAnimations()`، فالقفز بالزمن للخلف لا يعيد تشغيلها — ولذلك
يرتّب `preview.mjs` اللحظات تصاعديًا تلقائيًا.

## التعديل

**نقل مشهد أو تغيير مدّته:** عدّل `--t0` و`--dur` في `index.html` فقط — كل
حركات أبناء المشهد محسوبة بـ `calc()` نسبةً إليهما وتتبعه تلقائيًا. ثم حدّث
`DURATION` في `render.mjs` وقائمة النوافذ في `scene.js` (شريط الخرز السفلي).

**تغيير النصوص:** كلها مكتوبة مباشرة في `index.html`.

**إضافة حساب المتجر في الختام:** أضف سطرًا داخل `.lockup.out` في مشهد الختام،
وأعطه نفس نمط `.bridge-lat` في `scene.css`.

**استبدال الشعار:** ضع الملف الجديد مكان `brand/subha-logo.png` وأعد توليد
النسخ المفرّغة — الأمر المستخدَم مكتوب في `brand/HOW.md`.
